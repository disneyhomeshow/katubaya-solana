# katūbayá DApp

The web front end of the Farmer Core Solana Bridge for all four roles:

- **Farmers** and **customers**: onboarding, the market, checkout into escrow, order follow-up and
  the farmer's offers and payouts.
- **Warehouse operators** play the **yard**: the gate, four docks, the pickup counter, the road and
  the escrow vault of their warehouse, as an isometric map.
- **The program admin** plays the **program map**: every warehouse on a grid of plots, the roads
  between them, the market switch, and founding new warehouses.

- **Design**: the Katūbayá design system (tokens, components, logos, grafismo), the screen designs in
  the "Katūbayá DApp — telas iniciais" canvas and, for the yard and the map, the "Katūbayá
  gamificado" canvas (sprites, Broto the guide, animations).
- **Client**: the program client in `src/generated/` is generated by [Codama](https://github.com/codama-idl/codama)
  from the program's Anchor IDL, on top of `@solana/kit`.
- **Wallets**: any [Wallet Standard](https://github.com/wallet-standard/wallet-standard) wallet that
  supports `solana:signAndSendTransaction` (Phantom, Solflare, Backpack, …), through `@solana/react`.

## Run it

```bash
cd dapp
npm install
cp .env.example .env.local   # optional: cluster, RPC endpoint, mint symbols
npm run dev                  # http://localhost:5173
npm run build                # type-check and production build into dist/
```

`VITE_SOLANA_CLUSTER` picks `devnet` (default), `testnet`, `mainnet-beta` or `localnet`; `VITE_RPC_URL`
overrides the endpoint. The program must be deployed and `init_config` run on that cluster, or every
screen says so. Payment mints show by symbol when listed in `VITE_MINT_SYMBOLS`.

## Regenerate the program client

When the program changes:

```bash
npm run idl      # cargo builds the program with idl-build and writes idl/farmer_core.json
npm run codama   # renders src/generated/ from the IDL
```

`npm run idl` does what `anchor idl build` does (the `idl-build` feature prints the IDL from tests)
so it needs only `cargo`, not the Anchor CLI. Never edit `src/generated/` by hand.

## Decisions worth knowing

- **Units and prices** (README section 10). Quantities are typed in the unit the farmer sells in and
  stored in base units (kg → g, liter → ml). `price_minor` is per base unit, because the program
  computes `subtotal = qty * price_minor`; the screens show and take the price per selling unit
  and convert. A price per kg must therefore land on a whole minor unit per gram (3 decimals for
  USDC).
- **Ids**. `offer_id` and `order_id` are seconds since 2026-01-01 UTC: unique per farmer or per
  (offer, customer), ordered, and short enough to read as "Order #26179200".
- **Expiry**. The "Expires" date is the last day customers can order; `expires_at` is the start of
  the next local day, matching the program's inclusive `now >= expires_at`.
- **Every signature goes through the design system's `Transaction` dialog**: it lists what moves and
  every rent the wallet pays, simulates first (so a program error is explained before the wallet
  opens), then shows approve → send → confirmed, failed or declined. Errors are worded for people,
  mapped from `FarmerCoreError` codes.
- **Payout accounts**. `complete_order` requires the farmer's token account to exist, so publishing
  creates the farmer's associated token account for the mint when it is missing.
- **Not on chain, not on screen.** Photos (storage still undecided), changing an offer's price or
  stock, and request or profile timestamps have no program support, so those parts of the design
  show the honest state ("No photo yet", "publish a new offer") instead. `pack_ref` shows only as
  "Reference (unverified)".
- The quote deadline: `accept_delivery_fee` does not check `expires_at`, but after it the screen
  offers only "Close and refund", as the design does.

### The yard and the program map

- **The chain decides, the map shows.** Every piece mirrors an account or a status: a truck per
  delivery order waiting at the docks, people at the gate per pending request or farmer, the porter
  and customer at the counter for the oldest open pickup. The forklift, a truck pulling out, a
  customer walking in and Broto's lines are how the map shows what a transaction just did; they
  start only once Solana confirms it (the forklift drives to the dock while the wallet is open, and
  goes back to its rounds if the prompt is declined).
- **Docks are assigned in the browser**: the program has no docks, so a delivery order parks at the
  first free one in order of arrival and keeps it until it leaves; a fifth waits in the task list.
- **What changed while you watched.** The yard reads the warehouse again every 6 s and the map every
  10 s; new orders, accepted or rejected quotes and new people at the gate arrive as a toast and a
  line from Broto.
- **Where a warehouse stands.** The program stores no map, so the plot a warehouse was founded on
  rides in its `warehouse_id`: ids from the map are `(seconds since 2026 << 8) | (plot + 1)`. Any other
  id (a small one from a script, say) takes the first free plot, ring by ring, in id order. Each
  warehouse is reached by a road from the nearest one founded before it.
- **Fees go to the logistics wallet.** `complete_order` pays the farmer the subtotal less the
  service fee and sends the service and delivery fees to `config.logistics_wallet`, so the yard says
  so instead of "the warehouse receives". It creates the farmer's or the logistics wallet's token
  account when missing, paid by the operator.
- **Beyond the gamification design**, because the program supports them and the job needs them:
  turning a customer away (`revoke_customer`), closing an order past its deadline from the yard
  (`expire_order`), redrawing a warehouse's delivery area, pickup notes when founding, and the
  program set-up screen when `init_config` was never run. The two checkboxes before confirming a
  customer are required, not decorative.
- **Not on chain, not on screen.** Orders have no completion time, so the HUD says "Released"
  (all time) rather than "Released today", and "Recent on Solana" lists order creation times plus
  what you did in this session.
- **Light only.** The renders are lit for the light ground, so both games (and their transaction
  dialogs) stay light whatever the app theme. `prefers-reduced-motion` turns their animations off.
